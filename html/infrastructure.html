Infrastructure

Deze pagina documenteert de server infrastructuur van Zaroc. De server draait op 10.134.177.16 en host de website, de database, geautomatiseerde scripts en de back-up met externe opslag.

Server Setup & Database

1.1 Accounts & SSH

Eerst werden er gebruikersaccounts aangemaakt voor elk teamlid. Tijdelijke wachtwoorden werden veilig gedeeld via password link. Sudo-rechten werden enkel toegekend aan accounts die ze effectief nodig hebben, via /etc/sudoers.d/team_users (gezet op ALL) SSH-sleutelparen werden gegenereerd en wachtwoordlogin werd uitgeschakeld. We hebben ook een shortcut toegevoegd om hiermee makkelijk te kunnen inloggen. In de ssh config file (op Windows): 

Host (shortcut)
HostName INF102-T01.inf.kdg.be
User (username)

Als een extraatje, hebben wij een script gemaakt om users aan te maken en toe te voegen aan groepen (en eventueel sudo-permissies geven indien nodig)! sudo ./createUsers.sh (username).

1.2 PostgreSQL

PostgreSQL werd geïnstalleerd en geconfigureerd. Er werd een aparte database user 'game' aangemaakt met toegang tot de game-database. Externe toegang wordt beheerd via pg_hba.conf. De firewall laat enkel verbindingen op poort 5432 toe vanuit vertrouwde netwerken.

Webserver & Automatisering

2.1 Apache Webserver & Validator

Apache HTTP Server werd geïnstalleerd en geconfigureerd om de website te hosten op poort 80. De firewall werd aangepast om HTTP-verkeer door te laten. De websitebestanden staan onder /var/www/html met eigenaarschap root:apache. 

sudo dnf install httpd
sudo systemctl enable --now httpd
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload

Een serviceaccount svcteam werd aangemaakt voor het uitvoeren van geautomatiseerde scripts. Dit account heeft geen loginshell (/sbin/nologin). De HTML-validator controleert dagelijks om 12:00 alle webpagina's op validatiefouten. Het script draait als svcteam en schrijft zijn resultaten naar /opt/validator/data/. Vijf minuten later wordt check_errors.sh uitgevoerd en bij problemen wordt er een melding gestuurd naar alle teamleden.

2.2 Database Export naar JSON

Elk uur exporteert dbexport.sh de data uit PostgreSQL naar een JSON-bestand dat via de website publiek beschikbaar is. Het script verbindt met de database, exporteert naar CSV, converteert met Python naar JSON en kopieert het resultaat naar de juiste map.

Back-up & Netwerkanalyse

3.1 Back-up script

Het back-upscript draait dagelijks om 02:00 en voert de volgende stappen uit:

Back-up stappen

Mounten

De externe schijf /dev/sdb1 wordt gemonteerd op /mnt/external_backup en gecontroleerd op schrijfrechten.

Archiveren

Een .tar.gz archief wordt aangemaakt van /var/www/html, /opt/dbexport en /opt/validator.

Integriteit

Een SHA-256 hash wordt berekend en opgeslagen naast het archief. Bij een restore wordt de hash eerst geverifieerd.

Extern verzenden

Archief en hashbestand worden via SCP met een SSH-sleutel doorgestuurd naar de inf102-t02 server.

Opruimen

Back-ups ouder dan 14 dagen worden automatisch verwijderd van de externe schijf.

Unmounten

De externe schijf wordt ontkoppeld. Bij een fout in een eerdere stap gebeurt dit via een noodprocedure.

Elke stap wordt gelogd naar /opt/backup/log/backup.log. Bij een fout wordt de schijf veilig ontkoppeld en verstuurt het script een pushmelding via Pushover.

3.2 Network Sniffing & HTTPS Beveiliging

Tijdens network sniffing met Wireshark zagen wij dat data via HTTP (poort 80) volledig leesbaar was. Om dit op te lossen, hebben wij gewerkt met een Let's Encrypt certificaat. We koppelden hiervoor een nieuwe domein (via DuckDNS) zaroc-kdg.duckdns.org aan onze server.

HTTPS stappen

DNS bypassen

De school-DNS blokkeerde externe verbindingen. /etc/resolv.conf werd tijdelijk gericht naar Google DNS (8.8.8.8) zodat Certbot kon werken.

DNS-01 challenge

Omdat Let's Encrypt onze server niet via poort 80 kon bereiken, werd de certbot-dns-duckdns plugin gebruikt. Die plaatst automatisch de vereiste verificatiecode als TXT-record in de DuckDNS API.

Certificaat installeren

Na goedkeuring ontving de server fullchain.pem en privkey.pem. Deze werden gekoppeld aan de Apache configuratie voor HTTPS op poort 443.

HTTP → HTTPS redirecten

Alle HTTP-verzoeken op poort 80 worden automatisch doorgestuurd naar HTTPS. Het verkeer is daardoor beveiligd.

Database beveiliging

Ook PostgreSQL werd beveiligd: via certificaten en instelling ssl = on in postgresql.conf. De queries zijn nu niet meer zichtbaar.
